## Short answer

Match records using a stable identifier and define which fields the import is allowed to update. Staff-entered notes need an explicit preservation rule, especially when incoming files contain blanks or older values.

## Practical explanation

Back up the relevant records and test the import on a small permitted sample. Review how the system handles duplicate identifiers, missing fields and repeated imports. Keep imported source data distinguishable from staff updates where practical. Verify records with existing notes after the test. Use a documented merge process rather than assuming every value in the latest file should replace the current record.

## Example

A fresh website enquiry file may have an empty notes column. Importing that blank over a receptionist's callback history would erase useful work unless the update rules prevent it.
