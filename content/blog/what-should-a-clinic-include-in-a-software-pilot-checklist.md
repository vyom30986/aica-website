## Short answer

Define the workflow being tested, the staff involved, the records required and the measures that will indicate whether it works. Include a recovery process so the clinic can continue handling requests if the pilot tool is unavailable.

## Practical explanation

Test with synthetic records before using authorised live data. Check permissions, field mapping, status meanings and handovers. Train the participating staff and agree how issues will be reported. Compare results with the existing process using the same definitions. Record unresolved problems and decide which must be fixed before wider use. Keep the pilot scope clear so its results are interpretable.

## Example

A reception callback pilot can measure whether every request has an owner and outcome without claiming that the same tool has already been validated for clinical documentation.
